Reusable UI foundation

One system first. Screens second. React later.

Diarito 1.2.0 treats the component library as an internal framework: tokens define decisions, layout primitives define structure, components define reusable UI, and product patterns compose those pieces without creating one-off styling.

Governance

Rules that prevent visual drift

This is the part future React components should inherit almost literally.

1. reuse

If a shared component exists, a screen must use it instead of recreating its visual styling.

2. modify

Variants belong in the component library. Page CSS must not silently create alternate button, input, card or status designs.

3. compose

Screen CSS may arrange components. It should not restyle component internals.

4. tokens

New visual values first become tokens when genuinely needed. Random hex values and magic spacing numbers are not allowed in screen CSS.

5. react later

When migration begins, HTML classes become the visual contract for React components such as Button, Input, Card, Alert and NoteCard.
